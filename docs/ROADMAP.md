# SONORA roadmap

## Статус проекта

Поиск для приложения и сайта ведёт к воспроизведению в SONORA. При точном совпадении профиля Audius поиск дополнительно запрашивает его каталог, проверяет ID загрузившего трек и исключает недоступные потоки. Карточки исполнителей открывают поиск внутри SONORA, карточки записей предлагают найти доступную версию. Имя артиста в начале названия сторонней записи само по себе не считается кредитом, в том числе при сбое MusicBrainz.

## Что брать из существующих плееров

1. Единый поиск с явной доступностью, импорт плейлиста с предварительным просмотром совпадений и видимым исходным источником каждой записи. LANE публично описывает использование API Spotify и SoundCloud для поиска информации. Dotify показывает сценарии импорта, поиска и локальных файлов. [LANE](https://sklane.com/ru/terms-of-service) · [Dotify](https://dotify.fun/) · [Условия Dotify](https://dotify.fun/tos)
2. Восстанавливаемая очередь, предыдущая позиция и понятные состояния офлайна. Для Android опираемся на существующий Media3. Для личных библиотек изучаем OpenSubsonic и сценарии Tempo, Navidrome и Feishin. [Media3](https://github.com/androidx/media) · [Tempo](https://github.com/CappielloAntonio/tempo) · [Navidrome](https://github.com/navidrome/navidrome) · [Feishin](https://github.com/jeffvli/feishin)
3. Раздел профиля с историей, приватностью и управлением подключёнными аккаунтами. ListenBrainz — ориентир для добровольной передачи прослушиваний и независимого профиля истории. [ListenBrainz API](https://listenbrainz.readthedocs.io/en/latest/users/api/index.html)
4. При недоступности записи поиск на Android и в вебе предлагает поиск разрешённой версии по ISRC, исполнителю и названию. Совпадение требует явного запуска пользователем. Метаданные Spotify остаются в отдельном режиме API с правилами атрибуции платформы. Для подключения аккаунта предусмотрен OAuth с PKCE. [Spotify Search](https://developer.spotify.com/documentation/web-api/reference/search) · [Spotify Developer Policy](https://developer.spotify.com/policy)

Распознавание речи: https://developer.mozilla.org/en-US/docs/Web/API/SpeechRecognition и https://developer.android.com/reference/android/speech/RecognizerIntent. Веб использует доступный сервис браузера, Android — системный распознаватель и TextToSpeech. В интерфейсах указано, что речь обрабатывается этим сервисом, SONORA получает текст. Непрерывного скрытого прослушивания и активации ключевым словом нет.

Это доработка существующего помощника и алгоритма рекомендаций, не обучение отдельной модели. Опциональный LLM использует существующую серверную конфигурацию; при её отсутствии работает проверяемый разбор команд. Реальный LLM в текущей приёмке не проверен.

Финальная проверка этого этапа: сборка Next.js и Android assembleDebug успешна, 15 тестов проходят. APK: `/workspace/scratch/SONORA-assistant-ru-debug.apk`. Debug APK использует существующий адрес API; новые ответы сервера и персонализация появятся на устройстве после публикации соответствующего API. Подписанный релиз и production-деплой ещё не выполнены.

## 22 ноября 2026 — команды плеера и проверка реальных источников

- Реализовано на вебе и Android: «слушать [подборку]», «пауза», «продолжить», соответствующие русские варианты. Команды выполняются локально. Названия вроде «найди Пауза» остаются поисковыми запросами.
- Проверено в браузере с настоящим HTMLAudioElement и сгенерированным WAV: запуск очереди, повторный запуск без случайной паузы, две паузы подряд, возобновление; всего один API-запрос для исходной подборки.
- Исправлено различение отказа каталогов и отсутствия результата. Полный отказ возвращает HTTP 503 с русским сообщением, частичный — пометку о неполной выдаче. В ответ не включаются внутренние тексты ошибок источников.
- Реальная сетевая проверка: запрос MOODY GOOD вернул 14 записей; выбранный Audius-поток «Moody Good - a gem flip» вернул HTTP 206, audio/mpeg и 4096 байт. Это проверка доставки фрагмента, не полного прослушивания и не качества звука.
- По Кишлаку доступный звук в данной проверке не найден; MusicBrainz ответил 503. Для calm общий поиск вернул один воспроизводимый кандидат. Jamendo в локальном процессе не настроен. Эти результаты не подтверждают покрытие всех артистов.
- Рабочая среда требует NODE_USE_ENV_PROXY=1 для исходящих запросов Node 24. Это настройка локального запуска, не изменение production-сервера и не обход ограничений площадок.
- Остаются: живой русский микрофон и TTS на Android, проверка пользовательской истории на реальном аккаунте, production API + веб и подписанный APK с OTA. Непрерывный режим и активация ключевым словом не реализованы.
